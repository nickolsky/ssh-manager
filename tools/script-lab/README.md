# Проверка установочных скриптов

Три уровня, от быстрого к настоящему.

## 1. Без серверов: `dotnet test`

```powershell
dotnet test tests\SshManager.Tests
```

Проверяет каждый встроенный скрипт: описание и параметры читаются, значения по умолчанию проходят проверку,
все `@result` действительно записываются, в файле нет CRLF, скрипт рассчитан на Ubuntu/Debian.
Синтаксис bash: `bash -n src\SshManager.Core\Scripts\Builtin\*.sh` (и `shellcheck`, если он установлен).

## 2. Тестовый стенд: Ubuntu и Debian в Docker Desktop

Каждый «сервер» здесь — контейнер с systemd, sshd, sudo и **своим** Docker внутри, почти как чистый VPS.
Скрипты ставят Docker, nginx и сервисы по-настоящему. Нужен Docker Desktop (Linux-контейнеры).

```powershell
cd tools\script-lab
.\lab.ps1 up              # Ubuntu 24.04 (порт 2201) и Debian 12 (порт 2202)
.\lab.ps1 up -Extra       # ещё Ubuntu 22.04 (2203) и Debian 13 (2204)
```

### Автоматически

```powershell
.\lab.ps1 test                     # VLESS, Hysteria 2, AmneziaWG, оба статических сайта, File Browser
.\lab.ps1 test vless,amneziawg     # только эти
.\lab.ps1 test -Heavy              # плюс Nextcloud и Seafile (несколько ГБ образов, 10–20 минут)
```

Тест запускает скрипт так же, как программа (загрузка по SFTP, параметры в env, `sudo`, сбор результатов),
на всех серверах стенда параллельно, а потом проверяет результат клиентом:

| Скрипт | Что проверяется |
|---|---|
| VLESS REALITY | клиент Xray по ссылке из результата открывает сайт в интернете, для xhttp и для tcp (скрипт для Ubuntu или для Debian 12 — по ОС сервера) |
| Hysteria 2 | официальный клиент берёт ссылку `hysteria2://` как есть и открывает сайт; с obfs и без |
| AmneziaWG | ключ `vpn://` раскодируется так же строго, как в Amnezia VPN (длина, zlib, Adler-32) и содержит тот же конфиг; клиент AmneziaWG в отдельном контейнере, настроенный из ключа: рукопожатие, ping 10.66.66.1, интернет через NAT сервера; новое имя в списке добавляет клиента, убранное — удаляет, остальные не меняются |
| nginx | запуск от обычного пользователя через `sudo`; страница отдаётся, HTML экранируется; повторный запуск не трогает загруженный `index.html` |
| Caddy | страница отдаётся на заданном порту |
| File Browser | вход по сгенерированному паролю; смена пароля повторным запуском |
| Nextcloud | `status.php` = installed, администратор входит через API; пароль не остаётся в `.env` |
| Seafile | администратор получает токен API; пароль не остаётся в `.env` |

Полный вывод каждого запуска — в `%TEMP%\sshm-lab\<скрипт>-<сервер>.log`.

### Вручную, в программе

1. Добавьте серверы: `127.0.0.1`, порт `2201` / `2202`, пользователь `root`, пароль `lab-root`
   (или `lab` / `lab-user` — обычный пользователь с sudo, так тоже нужно проверить).
2. Правый клик → «Обновить информацию» (чтобы программа узнала ОС), затем «Установить ▸» → VPN / Веб-сервер / Облачные хранилища.
3. Смотрите вывод, результаты у сервера, мониторинг портов, «Файлы» → `/opt/amneziawg/clients`.

Со стенда в браузер на этом ПК проброшены порты (см. `compose.yml`): Ubuntu `18001`→8080 (Caddy),
`18002`→8081 (File Browser), `18003`→8000 (Seafile), `18004`→80 (nginx); у Debian то же на `18011–18014`.
Например, после «Статический сайт (Caddy)» с портом 8080 откройте http://localhost:18001.

VPN-клиенты на ПК к стенду подключить не получится: адреса в ссылках — внешний IP вашего интернета, а сам стенд
спрятан за NAT Docker Desktop. Для этого нужен настоящий сервер.

```powershell
.\lab.ps1 reset    # выбросить серверы и начать с чистых
.\lab.ps1 down     # удалить всё, включая тома
```

## 3. Настоящий VPS

Всё, чего стенд не покажет: работу через интернет и DPI, UDP у хостера, Let's Encrypt с настоящим доменом.

1. Дешёвый VPS с Ubuntu 24.04 или Debian 12 (для VPN хватит 512 МБ – 1 ГБ; для Nextcloud/Seafile нужно от 2 ГБ).
2. Добавьте его в SSH Manager, «Обновить информацию», запустите скрипт.
3. Проверьте клиентом:
   - **VLESS / Hysteria 2**: ссылку из результатов («Копировать значение») импортируйте в v2rayN, Hiddify
     или NekoBox (Windows / Android) — или отсканируйте телефоном: «Показать QR-код» у результата;
     откройте https://ifconfig.me: должен показаться IP сервера.
   - **AmneziaWG**: у сервера в «Результатах скриптов» → «Amnezia VPN — phone» → «Показать QR-код»,
     отсканируйте в AmneziaWG или Amnezia VPN (или «Копировать значение» и вставьте ключ `vpn://` в Amnezia VPN),
     проверьте https://ifconfig.me. Ключ `vpn://` собирается по исходникам Amnezia VPN — один раз проверьте,
     что приложение его принимает.
   - **Сайты и хранилища**: откройте адрес из результатов; для HTTPS создайте A-запись домена на IP сервера
     до запуска скрипта (подойдёт бесплатный домен DuckDNS).
4. Повторный запуск: ссылки и пароли не должны поменяться, сервисы должны подняться снова.
5. Если что-то не так: вывод и код выхода сохраняются в истории запусков у сервера,
   логи контейнера — `docker logs <имя>` во встроенном терминале.

Чек-лист перед выпуском: каждый новый скрипт хотя бы раз прогнать на реальном Ubuntu и реальном Debian,
а VPN — ещё и с телефона через мобильный интернет (там чаще всего стоит DPI).
