# SSH Manager

Личный Windows-инструмент для работы с большим количеством SSH-серверов:
хранение серверов, паролей и ключей в зашифрованном хранилище, запуск сессий в один клик,
автоматический перевод сервера с пароля на ключ и встроенный SSH-агент (аналог Pageant для OpenSSH),
который живёт в трее и стартует вместе с Windows.

## Быстрый старт

```powershell
.\publish.ps1                 # сборка в .\app
.\app\SshManager.exe          # первый запуск — создание мастер-пароля
```

Нужен .NET 10 Desktop Runtime и системный OpenSSH-клиент (есть в Windows 10/11).

При первом запуске программа попросит придумать мастер-пароль и предложит автозапуск
(галочка включена по умолчанию; меняется в «Настройки»). При автозапуске программа стартует сразу в трей
**заблокированной**; окно разблокировки появится при первом обращении к серверу или агенту.

## Возможности

- **Серверы**: название, группа, хост/IP, порт, пользователь, пароль или ключ, jump-хост, доп. аргументы ssh, заметки.
  Дерево с вложенными группами (`VPN/Европа`), которые сворачиваются и запоминаются; поиск (Ctrl+F) — в том числе
  по ОС, региону и контейнерам; двойной клик / Enter — подключиться, Ctrl+N — новый сервер, F5 — обновить всё.
- **Русский / English**: меню «Язык (Language)», меню трея или «Настройки» — переключается сразу, без перезапуска.
- **Мониторинг доступности**: TCP-подключение к SSH-порту и ответ sshd, по умолчанию раз в 5 минут (интервал
  меняется глобально и для каждого сервера). Если SSH не отвечает, но открыт хотя бы один отслеживаемый порт,
  сервер считается доступным (жёлтая точка). Цветная точка в дереве, уведомление в трее, когда сервер падает.
- **Аптайм**: каждая проверка пишется в `data\uptime`, колонка «Аптайм» показывает доступность за сутки / неделю /
  30 дней. «История доступности…» в контекстном меню — графики доступности и задержки за 24 ч … год и список
  отключений. Время, когда программа не работала, не считается ни доступностью, ни простоем.
- **Мониторинг портов**: для сервера отмечаются TCP-порты (443 VPN, 2053 панели…) — вручную или из найденных
  на сервере (`ss -tlnp`): «Мониторинг портов…» или «Следить за этим портом» в контекстном меню. Порт, который
  перестал отвечать, красный в колонке «Порты», сервер — жёлтый, в трее уведомление. Для порта с пробросом
  проверяется вся цепочка до целевого сервера.
- **CPU / память / диск**: после каждой успешной проверки программа заходит по SSH и читает `/proc`
  (колонки CPU, «Память» и «Диск» — свободное место на `/`; подсказка — load, диск, время работы).
- **Что на сервере**: при первом подключении (и при раскрытии сервера, если данные старше 10 минут) определяются
  дистрибутив Linux, Docker-контейнеры, известные сервисы (nginx, Xray, 3X-UI, WireGuard, OpenVPN, Marzban…),
  слушающие порты и пробросы iptables. Всё видно в раскрытом сервере; для контейнеров и сервисов — логи,
  статус и перезапуск в терминале.
- **Регион**: страна и город по IP (онлайн-сервис ipwho.is, запасной — ip-api.com; кэш 30 дней, отключается).
- **Пробросы портов (iptables)**: «Пробросы портов…» показывает существующие DNAT-правила и добавляет новые
  (`443 → другой сервер:443`, tcp/udp, диапазоны): DNAT + MASQUERADE + FORWARD, `ip_forward`, сохранение через
  netfilter-persistent / iptables-save (при необходимости предлагает поставить iptables-persistent).
  Пробросы видны в основном дереве — и исходящие, и входящие.
- **Установочные скрипты**: «Настройки → Установочные скрипты» (хранятся в зашифрованном vault), запуск — правым
  кликом «Установить ▸». Скрипт выполняется в окне программы: форма параметров, живой вывод, результаты
  сохраняются у сервера (раздел «Результаты скриптов» в дереве, «Копировать значение»). Для интерактивных
  установщиков есть кнопка «В терминале». ОС скрипта выбирается в выпадающем списке (несколько, можно с версией:
  `debian:12`), скрипты для ОС сервера показываются первыми.
  Встроенные скрипты: **VLESS REALITY (Xray в Docker)** для Ubuntu и для Debian 12 с маленьким диском
  (из [vless_docker_install_scripts](https://github.com/nickolsky/vless_docker_install_scripts)) — возвращают
  ссылку `vless://…` и ставят порт Xray на мониторинг.
- **Резервное копирование**: zip всей папки `data` в папку на диске или на сервер по SFTP, ротация, автобэкап раз
  в N часов, кнопка «Сделать бэкап сейчас». **Восстановление** — «Восстановить из копии…» (Настройки → Резервное
  копирование или меню «Файл»): последняя копия из папки/с сервера или любой `sshmanager-data-*.zip`, нужен мастер-пароль
  на момент бэкапа; текущие данные перед заменой сохраняются в `data\backups\before-restore-*.zip`.
- **Подключение в один клик**: сессия открывается во вкладке Windows Terminal (или новом окне / обычной консоли —
  см. настройки). По ключу — через встроенный агент, по паролю — пароль подставляется автоматически через
  `SSH_ASKPASS`. Ни пароль, ни приватный ключ не попадают в командную строку и на диск.
- **«Настроить вход по ключу»**: входит по сохранённому паролю, генерирует Ed25519-ключ (или берёт существующий),
  добавляет его в `~/.ssh/authorized_keys` (без дублей, права 700/600), проверяет вход по ключу и переключает сервер
  на ключ. Вход по паролю на сервере **не** отключается.
- **Ключи**: генерация Ed25519 / RSA-4096, импорт (OpenSSH, PEM, PuTTY .ppk, в т.ч. с passphrase),
  копирование публичного ключа, экспорт приватного (файл доступен только вашему пользователю Windows).
- **Проверка ключей серверов**: при первом подключении показывается отпечаток ключа сервера; изменение ключа
  выдаётся как предупреждение. Используется собственный `data\known_hosts`.
- **Трей**: быстрый доступ к серверам (меню «Подключиться»), блокировка, выход. Кнопка закрытия окна сворачивает в трей.
- **Автоблокировка**: после N минут простоя ПК (по умолчанию 120) и, по желанию, при Win+L.
- **Консоль**: `sshm <имя сервера>` подключает к сохранённому серверу прямо в текущем терминале,
  `sshm list` — список серверов. Добавьте папку `app` в PATH, чтобы вызывать `sshm` откуда угодно.

## SSH-агент

Агент поднимается на named pipe `\\.\pipe\openssh-ssh-agent` — это стандартный адрес, который используют
`ssh.exe`, `git`, VS Code Remote-SSH. Если этот pipe уже занят другим агентом (например, **1Password** или
служба Windows `ssh-agent`), SSH Manager использует `\\.\pipe\sshmanager-agent-<пользователь>`.
Сессии, запущенные из SSH Manager, работают в обоих случаях. Чтобы внешние программы тоже брали ключи
из SSH Manager, освободите стандартный pipe (например, отключите SSH-агент в 1Password) или задайте
переменную окружения пользователя:

```powershell
[Environment]::SetEnvironmentVariable('SSH_AUTH_SOCK', '\\.\pipe\sshmanager-agent-<пользователь>', 'User')
```

Точный адрес агента показан в строке состояния главного окна. Пока хранилище заблокировано, агент ключей
не отдаёт (при обращении клиента показывается окно разблокировки — отключается в настройках).

## Данные и безопасность

Все данные лежат в `SSHManagement\data` (папка в `.gitignore`):

| Файл | Содержимое |
|---|---|
| `vault.dat` | серверы, пароли, приватные ключи — AES-256-GCM, ключ из мастер-пароля через Argon2id (64 МБ, 3 итерации) |
| `backups\` | 20 последних версий `vault.dat` и снимки `before-restore-*.zip` перед восстановлением |
| `settings.json` | настройки интерфейса (без секретов) |
| `known_hosts` | ключи серверов в формате OpenSSH |
| (в `vault.dat`) | собранные сведения о серверах (ОС, контейнеры, регион), отслеживаемые порты, установочные скрипты |
| `pub\` | публичные ключи (нужны `ssh.exe`, чтобы выбрать нужный ключ из агента) |
| `uptime\` | история проверок доступности (CSV на сервер: время, состояние, задержка), хранится 400 дней |

Резервная копия = копия папки `data` + мастер-пароль (раздел «Резервное копирование» делает это автоматически;
для восстановления распакуйте архив в папку `data`). **Забытый мастер-пароль восстановить нельзя.**
Папку данных можно переопределить переменной окружения `SSHMANAGER_DATA`.

## Свои скрипты с параметрами и результатами

Параметры и результаты описываются комментариями в самом скрипте — по ним строится форма запуска:

```bash
#!/usr/bin/env bash
# @name    Мой сервис
# @os      ubuntu,debian:12
# @description Что делает скрипт (показывается в окне запуска; @description_en — по-английски)
# @param   DOMAIN  text   required label="Домен" default=example.com hint="Подсказка под полем"
# @param   MODE    choice options=fast,safe default=safe label="Режим"
# @param   PATH_X  text   default=/x when=MODE=fast          # поле видно только при MODE=fast
# @param   PORT    number default=8443 label="Порт"
# @param   DEBUG   bool   label="Подробный вывод"            # 1 / 0
# @param   TOKEN   secret label="Токен"                      # скрыто при вводе, не сохраняется в истории
# @result  URL     label="Ссылка"
# @result  PORT    label="Порт" monitor=MyService            # значение-порт ставится на мониторинг
set -euo pipefail
echo "Ставлю на $SSHM_SERVER_NAME ($SSHM_HOST): $DOMAIN $MODE"
echo "URL=https://$DOMAIN:$PORT" >> "$SSHM_RESULT"
echo "PORT=$PORT" >> "$SSHM_RESULT"
```

Параметры приходят переменными окружения (через файл в `/tmp`, не через командную строку), `label_en=` / `hint_en=`
задают английский текст. Результат — строки `ИМЯ=значение` в файле `$SSHM_RESULT`; последние значения видны у сервера,
история запусков (параметры без секретов, код выхода, хвост вывода) тоже хранится в vault.

## Структура решения

```
src/SshManager.Core   хранилище, криптография, форматы ключей, SSH-агент, IPC, запуск ssh, настройка ключей (SSH.NET),
                      строки RU/EN, мониторинг, метрики, инвентаризация, GeoIP, iptables, скрипты, бэкап
src/SshManager        WPF-приложение: окна, дерево серверов, трей, автозапуск, автоблокировка
src/sshm              консольный помощник: вкладка терминала, SSH_ASKPASS, `sshm <сервер>`
tests/SshManager.Tests  unit-тесты + совместимость с ssh-keygen/ssh-add + e2e
```

Тесты: `dotnet test`. Сквозной тест с настоящим sshd включается переменной
`SSHM_E2E=host:port:user:password` (используйте одноразовый тестовый сервер/контейнер; для проверки
пробросов нужен root и `--cap-add NET_ADMIN`).
